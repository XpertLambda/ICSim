Why Vehicle Security MattersPourquoi la Sécurité Automobile

In 2015, security researchers Charlie Miller and Chris Valasek demonstrated a remote compromise of a Jeep Cherokee via its cellular interface, gaining control over the CAN bus and ultimately the vehicle's brakes and steering at highway speed. The attack was possible because the CAN protocol - designed in the 1980s for isolated networks - has no authentication, no encryption, and no concept of a trusted sender. En 2015, les chercheurs en sécurité Charlie Miller et Chris Valasek ont démontré une compromission à distance d'une Jeep Cherokee via son interface cellulaire, prenant le contrôle du bus CAN et finalement des freins et de la direction du véhicule à grande vitesse. L'attaque était possible parce que le protocole CAN - conçu dans les années 1980 pour des réseaux isolés - n'a ni authentification, ni chiffrement, ni notion d'émetteur de confiance.

Real-world consequenceConséquence réelle

Any process that can write to the CAN bus has the same authority as a legitimate ECU. There is no way for a receiving module to distinguish an injected frame from a real one. Tout processus capable d'écrire sur le bus CAN a la même autorité qu'un véritable calculateur (ECU). Il est impossible pour un module récepteur de distinguer une trame injectée d'une trame réelle.

CAN (Controller Area Network, ISO 11898) was designed by Bosch in 1983 as a cost-effective way to replace hundreds of point-to-point wires with a single two-wire bus. Core Properties - and Why They Are DangerousPropriétés fondamentales - et pourquoi elles sont dangereuses

No source addressing. A CAN frame carries an arbitration ID (the signal type) and data. There is no sender field. A receiving ECU cannot know which node sent a frame. Pas d'adressage source. Une trame CAN porte un ID d'arbitrage (le type de signal) et des données. Il n'y a pas de champ émetteur. Un ECU récepteur ne peut pas savoir quel nœud a envoyé une trame.

No authentication. Any node can transmit any arbitration ID. There is no cryptographic signature, no session token, and no challenge-response mechanism. Pas d'authentification. N'importe quel nœud peut transmettre n'importe quel ID d'arbitrage. Il n'y a pas de signature cryptographique, pas de jeton de session, et pas de mécanisme défi-réponse.

Priority by ID. Lower arbitration ID wins bus access during simultaneous transmission. This is a feature for safety (brakes win over audio), but an attacker can exploit it by flooding with a low ID. Priorité par ID. L'ID d'arbitrage le plus bas remporte l'accès au bus lors d'une transmission simultanée. C'est une fonctionnalité de sécurité (les freins l'emportent sur l'audio), mais un attaquant peut l'exploiter en inondant avec un ID faible.

An honest word about a broadcast busUn mot honnête sur un bus de diffusion

CAN is a broadcast medium: once a frame is on the wire it cannot be taken back. So an attacker can always put a frame on the bus and any node can always read it. Signing and Verifying Every Signal Frame Signer et vérifier chaque trame de signal

SecOC (AUTOSAR Secure Onboard Communication) gives each broadcast frame a short message authentication code (MAC) and a freshness counter. The controller signs each frame as it sends it; the instrument cluster verifies it and applies a strict verify-or-reject policy - it acts on a frame only if the MAC checks out and the counter is fresh, otherwise it rejects it. An attacker without the key cannot produce a valid MAC, so a forged frame is rejected. A captured frame replayed later carries a stale counter and is rejected too. SecOC (AUTOSAR Secure Onboard Communication) donne à chaque trame diffusée un court code d'authentification (MAC) et un compteur de fraîcheur. Le contrôleur signe chaque trame à l'envoi ; le combiné la vérifie et applique une politique stricte vérifier-ou-rejeter - il n'agit sur une trame que si le MAC est valide et le compteur frais, sinon il la rejette. Un attaquant sans la clé ne peut produire un MAC valide, donc une trame forgée est rejetée. Une trame capturée puis rejouée porte un compteur périmé et est rejetée aussi.

Three things to be clear aboutTrois points à clarifier

No confidentiality. CAN is a broadcast bus; SecOC provides integrity and authenticity, not secrecy. An attacker can still sniff every frame and read the VIN, and real cars do not encrypt CAN either. What changes is that forgery and replay no longer work. Pas de confidentialité. Le CAN est un bus de diffusion ; SecOC fournit l'intégrité et l'authenticité, pas le secret. # standard 11-bit ID 0x244, 5 data bytes -> 100 mph

# extended 29-bit ID (8 hex digits), 8 data bytes - used by real UDS/OBD ECUs

# RTR: a remote request - asks another node to send ID 0x244, carries no data
cansend vcan0 244#R
What is the #R (RTR) form?C'est quoi la forme #R (RTR) ?

RTR = Remote Transmission Request. Instead of carrying data, the frame sets the RTR bit to ask whoever owns that ID to transmit it. You send 244#R and, on a real bus, the ECU responsible for 0x244 answers with the current data frame - a way to poll a value without knowing it. It is a legacy CAN feature: modern designs rarely use it, the ICSim ECUs do not answer it, and CAN FD drops it entirely. It is here so you recognise it when a capture or a tool shows an R. Write it as ID#R (no data bytes follow). RTR = Remote Transmission Request (requête de transmission distante). Au lieu de porter des données, la trame met le bit RTR pour demander au propriétaire de cet ID de la transmettre. Vous envoyez 244#R et, sur un vrai bus, l'ECU responsable de 0x244 répond avec la trame de données courante - une façon d'interroger une valeur sans la connaître. C'est une fonctionnalité héritée : les conceptions modernes l'utilisent rarement, les ECU d'ICSim n'y répondent pas, et le CAN FD la supprime totalement. Elle est ici pour que vous la reconnaissiez quand une capture ou un outil affiche un R. Écrivez-la ID#R (aucun octet de données ne suit).

canplayer ReplayRejouer

Replay a candump -l log back onto the bus with its original timing. This is what powers the "capture the unlock frame, then replay it" attack.Rejouer un journal candump -l sur le bus avec son timing d'origine. C'est ce qui alimente l'attaque « capturer la trame de déverrouillage, puis la rejouer ».

canplayer -I <logfile> <DST=SRC>
The channel-mapping argument is requiredL'argument de mappage de canal est requis

Unlike the others, canplayer takes no bare interface. Instead you give it a DST=SRC pair that maps the interface name recorded in the log onto the interface to send on. Since we both captured and replay on vcan0, that pair is vcan0=vcan0. Forgetting it is the usual reason a replay does nothing. Contrairement aux autres, canplayer ne prend pas d'interface seule. Vous lui donnez une paire DST=SRC qui associe le nom d'interface enregistré dans le log à l'interface d'émission. Comme on a capturé et rejoue sur vcan0, cette paire est vcan0=vcan0. L'oublier est la raison habituelle pour laquelle un rejeu ne fait rien.

Record, then replayEnregistrer, puis rejouer
Replay once / loop it / ignore timingRejouer une fois / en boucle / sans timing
# 1. record the bus to a log file (Ctrl-C to stop)
candump -l vcan0

# 2. replay it once - DST=SRC maps the log's vcan0 onto vcan0
canplayer -I candump-2026-07-26_120000.log vcan0=vcan0

# loop forever, back-to-back with no timing gaps
canplayer -l i -t -I candump-2026-07-26_120000.log vcan0=vcan0
